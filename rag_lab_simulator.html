Key idea: RAG doesn't usually retrain the model on your documents. It makes relevant information available at question time.

Chunking splits long documents into smaller passages that can be retrieved independently. Smaller chunks are precise but may lose context; larger chunks preserve context but can include irrelevant text.

0 chunks
Try this: Change the chunk size and chunk again. Notice how the number and boundaries of chunks change. Production systems may use token counts, overlap, headings, or semantic boundaries.

An embedding model converts each chunk into a numerical vector that represents aspects of its meaning. Real embeddings have many dimensions; this toy demo uses a tiny interpretable vector.

Important distinction: a vector is not a compressed sentence you can read directly. It is a numeric representation used to compare semantic similarity. These demo numbers are illustrative, not generated by an actual embedding model.

The vector database (or vector index) stores vectors alongside their original chunk text and metadata. At query time, the system searches for vectors near the query vector.

0 records
Think of each record as: vector + chunk text + source document + metadata. The text is what the LLM can later read; the vector helps locate it.
Real-world note: retrieval quality depends on embeddings, chunking, filters, ranking, and the question. Some systems combine vector search with keyword search and reranking.

What this simulator does

Uses a lightweight word-overlap similarity heuristic to illustrate ranking. The embedding vectors are made from simple keyword categories, not a neural embedding model. The answer is assembled from retrieved passages, not generated by an actual LLM.

RAG vs. model training

Training / fine-tuning: changes model parameters. RAG: fetches relevant external information at query time. RAG can make information easier to update and cite, but it doesn't guarantee correctness.

Learning tip

Run the same question with different chunk sizes and Top K values. Compare which evidence appears and whether the answer improves or gets noisier.
